# Game briefs

**Rule: no game is built before its brief exists here.** One file per game: `docs/games/<game-id>.md`. The brief is the contract for the rules package, the bot, the scene and the e2e test.

## Template

```md
# <Game name>

## The real game
Rules as people actually play them (cite a source). Win condition, turn order, edge cases, common house rules we offer as variants.

## What makes it feel right
The 3–5 things that make this game satisfying (e.g. the arc of a ball, the tension of a close race).

## How the best apps do it
2–4 reference apps/games: view/camera, controls, what reviewers praise and complain about.

## Our design
- View & art (flat, cute, crisp; which colors; what's animated)
- Controls on one phone (1P, 2P facing each other, 3–4P)
- Physics / rules engine (what's simulated, fixed step, determinism)
- Bot per tier (Pip / Bo / Zed / Nova): what changes between levels
- Sounds & haptics
- How it's clearly different from our other games

## Tests
Rules unit tests, bot-tier test, e2e steps.
```
